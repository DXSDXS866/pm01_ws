# voice_interaction 技术文档

PM01 人形机器人语音交互模块。部署于机器人计算单元（Jetson Orin NX），对接 PM01 运控 SDK（`interface_protocol` 消息包）。

本文档描述实际实现，可作为代码阅读与维护的索引。

---

## 1. 系统概述

- 一条链路打通 **语音 → 意图 → 动作 → 语音回复**：
  - **感知**：本地麦克风采集 + 能量 VAD 断句 + 阿里 **Paraformer** 流式 ASR。
  - **大脑**：阿里 **Qwen**（`qwen-plus`）大模型，**function call** 将意图解析为机器人工具调用。
  - **表达**：阿里 **CosyVoice**（`cosyvoice-v2`）云端 TTS，本地 `ffmpeg + aplay` 播放。
  - **躯干**：ROS2 动作桥 `MotionBridge` 将工具调用翻译成 PM01 运控话题/服务指令。
- 所有云服务（ASR / LLM / TTS）均经阿里云 **DashScope**，需 `DASHSCOPE_API_KEY`。
- 关键限定：本机**主要行走方式为视觉跟随**（`set_follow`），`walk` 速度接口在真机上未接通，`SYSTEM_PROMPT` 明确禁止 LLM 用 `walk`/`switch_motion` 行走。

## 3. 系统架构与数据流

```
           ┌───────────────────────── 机器人计算单元 (Jetson Orin NX) ─────────────────────────┐
           │                                                                          │
  麦克风 ──►│ MicrophoneRecorder ─► VAD(能量) ─► ASRClient(Paraformer, 流式)         │
  (16kHz)   │                              │  partial / 整句文字                     │
           │                              ▼                                          │
           │                        VoiceInteractionNode ▎                           │
           │            ┌───────── 唤醒词判定 / 指令优先级调度 ──────────┐            │
           │            ▼                                             ▼            │
  扬声器 ◄─│  SpeakerPlayer ◄─ TTSClient(CosyVoice) ◄─────────────────┐            │
           │      ▲           （LLM 回复 / 固定 MP3）                  │            │
           │      └──────────  也播放 media/*.mp3 固定素材 ◄───────────┤            │
           │                                                          ▼            │
  其他节点 ◄─│             MotionBridge ─────────────► PM01 运控 SDK              │
           │                                                                          │
           └──────────────────────────────────────────────────────────────────────────┘
```

### 3.1 线程模型

单 ROS2 节点，多线程协作，**绝不阻塞麦克风监听线程**：

| 线程 | 职责 |
|------|------|
| ROS2 executor 主线程 | `rclpy.spin` 处理回调（含 motion_state、follow 状态、速度/挥手定时器） |
| `_mic_loop` | 持续读麦克风 → VAD → 流式 ASR。**最严格的实时约束线程** |
| LLM worker（每指令新建） | `LLMClient.chat` 网络调用、执行工具、TTS 合成播放 |
| MP3 worker | 本地 MP3 播放 |
| 手势 worker | `execute_tool('gesture')` 内部轮询服务响应（最长 5s） |
| 站立化 worker | 停跟随后延时切 `pd_stand` |

越短耗时/越关键的动作尽可能留在 `_mic_loop` 或轻量回调里；会 sleep 或网络阻塞的工作一律丢到后台线程，避免卡住下一句唤醒。

## 4. 模块详解

### 4.1 audio_io.py — 音频采集与播放

**`MicrophoneRecorder`**
- 参数：`CHUNK=1600` 采样帧，`SAMPLE_RATE=16000`，单声道 `paInt16`。
- `read_chunk()` 用 `exception_on_overflow=False`，缓冲溢出不抛异常、返回静音块，避免采集卡噪音死。
- `device_index=None` 表示系统默认；`voice_node` 中 `mic_device_index<0` 时传 `None`。

**`SpeakerPlayer`**
- 播放链路：`MP3(bytes) → ffmpeg 转 WAV → subprocess aplay`（用到系统 `ffmpeg`，非重采样）。
- 临时文件写 `/tmp`，播放结束 `finally` 清理。
- `stop()` 打 `_interrupted` 标记并 `kill()` aplay——被“你好小智”打断时活体被强杀，属**正常现象**。
- `is_playing()`：`_proc` 存活即视为播放中。

### 4.2 vad.py — 断句

- 短时能量（RMS）> `energy_threshold` 判有人说话；持续静音达 `silence_ms` 判一句话结束。
- `silence_duration_ms // chunk_ms` 换算成静音帧数，`chunk_ms=100`。
- 可选 `webrtcvad` 叠加（`use_webrtc=True` 且已安装）：按 30ms 帧送检、过半数帧为语音才判说话，用于抑制能量法误判（如空调声持续超阈值导致 `end_of_utterance` 永不触发）。
- `process()` 返回三态：`'speaking' / 'silence' / 'end_of_utterance'`。

### 4.3 asr_client.py — Paraformer 流式识别

- 模型 `paraformer-realtime-v2`，`language_hints=['zh','en']`。
- 每次 `start()` **重读环境变量** `DASHSCOPE_API_KEY`，兼容服务化后配 key 场景。
- 回调 `on_event` 维护 `_finals`（已完成句，**追加**）与 `_partial`（当前进行句）：
  - `RecognitionResult.is_sentence_end(sentence)` → 追加到 `_finals` 并清空 `_partial`；
  - 否则 → 只更新 `_partial`。
  > 历史 bug：完成的句子若覆盖而非追加，多句会话只会保留最后一句。
- `get_partial()` 返回 `''.join(_finals)+_partial`，供“机器人说话时用唤醒词打断”用。
- `stop()` 在 `stop` 后 `wait(timeout=5.0)` 等服务端把最后一句回传完，避免丢尾。

### 4.4 tts_client.py — CosyVoice 合成 + 播放

- `SpeechSynthesizer(model=cosyvoice-v2, voice=longshu_v2)` —— **换 voice 必须同步换 model**（v2 配 `*_v2` 人物名）。
- 网络兜底：对每次 `call` 失败重试 1 次，间隔 1s，缓解演示偶发握手超时。
- 合成得到 MP3 字节 → 复用 `SpeakerPlayer.play_mp3` 播放。
- 默认男声 `longshu_v2`（温暖男声）；另可选 `longxiang_v2 / longxiaochen_v2 / longwan_v2`。

### 4.5 llm_client.py — Qwen function call

- 模型 `qwen-plus`（可 `qwen-turbo` 更快省 / `qwen-max` 更强）。
- `SYSTEM_PROMPT` 注入角色设定与规则（见 §8 安全与规则）。
- `TOOLS` 定义 5 个机器人工具：`walk / switch_motion / wave_hand / gesture / emergency_stop / set_follow`（参数 schema 见 §7）。
- 对话历史 `max_history=10`（保留 system + 最近轮），并发 `chat()` 用 `threading.Lock` **串行化**整段（history 是共享可变状态）。
- 解析 `msg.tool_calls`（OpenAI 兼容格式），返回 `(reply_text, tool_calls)`；失败时 pop 掉 user 消息防污染历史。

## 5. 唤醒机制

### 5.1 唤醒词正则

唤醒词是 **“你好小X”**（任意一字）：
```python
_WAKE_RE = re.compile(r'你好小.')
```
原因：ASR 把“小智”识别成各种同音字（小志/小城/小程/小乘…），枚举清单永远漏，用通配正则任何同音字/错字都能命中。

### 5.2 文本归一化 `_normalize_text`

1. 去空白 + 全半角标点（，。！？；：等等）。
2. **同音字归一到“小智”**：`小[陈城程乘辰晨臣诚承呈橙] → 小智`。原文发给 LLM 会让模型纠结自己名字甚至自起外号。

### 5.3 三种输入路径（`_process_recognized_text`）

| 情况 | 触发条件 | 处理 |
|------|---------|------|
| 1 | 当前句**含唤醒词** | 作废上一轮对话 → 打断当前输出 → 开唤醒窗口（8s）；喊完词只剩“你好小智”则 `return` 等下一句；否则直接执行词后命令（兼容“你好小智，跟着我”连读） |
| 2 | 已唤醒且在窗口内（`time.time() < _awake_until`） | 直接执行这句话 |
| 3 | 未唤醒 | 打 `💤 未唤醒，忽略` 日志，不进 LLM |

## 6. 指令优先级与调度（`_execute_command`）

一次唤醒只执行一条命令。匹配顺序**严格自上而下**，一旦命中即 `return`：

```
1. 直连指令（不进 LLM，零延迟）      ← 安全关键 / 快速响应
2. （可选）本地音频播放              ← 由部署方自行提供素材
3. 普通对话 → LLM function call
```

### 6.1 直连指令（第 0 优先级）

匹配 `_match_direct_command`，返回 `(kind, value)`：

| kind | 触发 | 说明 |
|------|------|------|
| `gesture` | 文本含“手势”或“交警”，逐词长优先匹配 | 见 §7.5 手势，含走/站立态校验 |
| `follow_off` | `停止跟随/别跟着/别动/停下/站住…` | 停跟随（最优先于开跟随，因“别跟着我”含“跟着我”） |
| `follow_on` | `跟着我/开始跟随/跟上我…` | 开跟随 |

> 为什么直连：跟随开关是**安全关键指令**，LLM 链路慢且曾被真机实测漏发（2026-08-31），所以关键词命中直接执行，喂 worker 线程不堵麦克风。

### 6.2 LLM 对话（第 2 优先级）

`_handle_utterance`（worker 线程）：
1. `LLMClient.chat` → `(reply, tool_calls)`。
2. 检查 `turn_id` 是否仍为当前轮（重新唤醒即作废，防止过期回复执行）。
3. 依次执行每个 `tool_calls`（`bridge.execute_tool`），执行前再校验 turn_id。
4. 无异常则 `tts.speak(reply)`。

## 7. 动作机制（motion_bridge.py）

### 7.1 原则：状态机**不允许跳跃**

PM01 真机验证的行走链：

```
idle → passive → pd_stand → rl_basic → body_vel_cmd(100Hz 持续速度)
```

收到 `walk` 而当前不在行走状态时，不立即发速度，而是挂起 `_pending_walk`，沿 `_WALK_LADDER` **逐级请求切换**，每级等 `/motion/motion_state` 确认后再走下一级，到达行走态才真正发速度。

### 7.2 行走链推进细节

- 行走判定 `_WALK_STATES = {rl_basic, rl_amp, rl_terrain, walk}`。`'walk'` 是第二套开发 SDK 的行走名，2026-08-31 从 运控固件二进制 strings 实测抠出，不加会导致跟随/行走中再说“向前走”被当链外状态切 passive 瘫软。
- 超时：每级 `_WALK_STEP_TIMEOUT=8s`，状态一变化即顺延（起立可能要好几秒）。
- 重发：同级同目标不刷屏，但超 `_HOP_RETRY_INTERVAL=2s` 且状态没变就补发一条，防单条请求丢失卡死。
- 不可达即放弃：若运控明确给出 `available_transition_motions` 且目标不在其中，取消命令、不硬切。
- `_next_walk_hop`：链上取下一跳；不在链上（未知/旁支如 `joint_bridge`）先回 `passive`。

### 7.3 速度发布

- `_start_walk` 立即发一次，再起 **10ms（100Hz）timer** 持续发 `BodyVelCmd` 到 `/motion/body_vel_cmd`。
- 普通“停下”= 速度归零（`_current_vel=None` + stop timer + 连发 0），**不切 passive**。
- **限速常量**（第一阶段真机调试）：`_MAX_VEL_X=0.15`、`_MAX_VEL_Y=0.10`、`_MAX_VEL_YAW=0.30`。LLM 给多大都会被 clamp 进来，现场嫌快/慢只改文件顶部这三个数。

### 7.4 挥手 wave_hand

- 通过 `JointOverrideCommand` 覆盖上肢关节（右臂 J18/19/21，左臂 J13/14/16），`stiffness=50, damping=1`。
- 需前置状态 `lower_body_balance`。不在则 `_pending_wave` 挂起并先请求切到该状态，`_check_pending_wave` 在进入后真正挥，5s 超时自动取消。
- 挥手 3s 后 `_clear_wave` 解除覆盖（weight=0 回零位）。

### 7.5 交警手势 gesture

- 通过 `/motion/gesture`（`MotionGesture` **服务**）执行，走 worker 线程轮询等待（`_GESTURE_TIMEOUT=5s`，内部 `sleep(0.05)` 不堵主线程）。
- 执行前先清 pending walk、停速度 timer、发零速，**`sleep(0.3)` 让零速落地**再调服务，防止手势与 100Hz 速度流打架。
- 手势 ID：`0归位 1停止 2直行 3左转弯 4左转弯待转 5右转弯 6变道 7减速慢行 8靠边停车`。
- 服务不可用（`wait_for_service` 2s）或响应超时/失败均有日志。

### 7.6 走/手势安全校验（voice_node 层）

- **跟随中**做手势：`_follow_active` 为真 → 拒绝并提示“请先说停止跟随”（行走中摆臂破坏平衡直接倒）。
- **`walk` 态**做手势：提示“还没站稳，请先说停止跟随”直接 return，由停跟随链路自动 walk→pd_stand（约 1.5s）。

### 7.7 紧急停止 emergency_stop

与普通“停下”不同：**速度归零 + 切 passive**。`_do_emergency_stop`：清 pending walk / pending wave → 停速度 timer → 发零速 → 发 `switch_motion('passive')`。

### 7.8 ROS2 发布/订阅/服务清单

| 方向 | 话题/服务 | 类型 | 用途 |
|------|-----------|------|------|
| Pub | `/motion/body_vel_cmd` | `BodyVelCmd` | 机体速度（100Hz） |
| Pub | `/motion/set_motion_state` | `MotionStateRequest` | 状态切换 |
| Pub | `/motion/joint_override_command` | `JointOverrideCommand` | 上肢覆盖（挥手） |
| Pub | `/vision_follow/set_follow` | `std_msgs/Bool` | 视觉跟随开关 |
| Sub | `/motion/motion_state` | `MotionState` | 当前运动状态（**BEST_EFFORT**，见 QoS 注记） |
| Sub | `/vision_follow/safety_bridge_status` | `std_msgs/String` | 跟随侧安全桥状态（JSON） |
| Client | `/motion/gesture` | `MotionGesture`(srv) | 交警手势 |

> **QoS 注记（重要）**：`.163` 运控 SDK 的 `/motion/motion_state` 用 **BEST_EFFORT** 发布，默认 RELIABLE 订阅会静默失配、一条都收不到，导致站立化/爬链全瞎。故 `MotionBridge` 显式用 `QoSProfile(reliability=BEST_EFFORT)` 订阅。

## 8. 视觉跟随联动与守卫

### 8.1 跟随状态来源

`VoiceInteractionNode` 订阅 `/vision_follow/safety_bridge_status`（JSON 字符串），`state=="FORWARDING"` 即视为跟随中，存入 `_follow_active`。解析失败按“未跟随”处理（守卫放行）。

### 8.2 跟随守卫（`_FOLLOW_GUARDED_TOOLS`）

跟随中，LLM 若再调 `{walk, switch_motion, wave_hand, gesture, emergency_stop}` 一律**拦截**：
- `walk/switch_motion/wave_hand/gesture`：本机行走由跟随模式负责，误触发会把状态切乱甚至切 passive 瘫软 → 提示“我正在跟随模式，如需手动控制请先说停止跟随”。
- `emergency_stop` 特判：改为 `set_follow(False)`（让安全桥零速刹住），**不切 passive**，急停不播报。
> 原因：跟随中 `walk` 状态不在语音侧状态表里，会被当链外状态请求切 passive 瘫软。

### 8.3 set_follow 细节（MotionBridge.set_follow）

- **开启**：作废未执行的站立化请求；若当前不在行走态，先请求切回 `walk`（pd_stand 下速度指令无效不会迈步）；再发 `Bool(True)`。
- **停止**：发 `Bool(False)`；随后 `_stand_after_stop` 延时 `_FOLLOW_STOP_SETTLE_SEC=1.5s` 切 `pd_stand`——先让安全桥零速脉冲把机器人停稳，行走中直接切站立会前倾。
  - 用 `_stand_request_id` 让过期请求作废：快速连喊“停/走”只认最新一条。
  - 已是 `pd_stand` 则跳过；其他状态（含未知）一律发 `pd_stand`，顶多被固件拒，比静默不切强。

## 9. 输出打断机制

- 唤醒词命中（含机器人**正在说话时**实时看 ASR partial 命中“你好小智”）→ 触发 `_stop_current_output()` → `SpeakerPlayer.stop()` 强杀 aplay，即时打断 TTS 或 MP3。
- `_is_output_active()` 判定：`player.is_playing()` 或 `_media_active`。
- MP3 被打断时 aplay 被 kill 会打 warning，属正常。

## 10. 配置参数（config/params.yaml）

| 参数 | 默认 | 说明 |
|------|------|------|
| `energy_threshold` | 500 | VAD 能量阈值，环境噪声 RMS 的 2~3 倍（`tools/tune_vad.py` 辅助校调） |
| `silence_ms` | 800 | 句尾静音时长(ms)断句；说话慢可加大，要快响应可减小 |
| `mic_device_index` | -1 | 麦克风索引，-1=默认；`python3 tools/list_audio_devices.py` 查 |
| `llm_model` | qwen-plus | 可 qwen-turbo（更快省）/ qwen-max（更强） |
| `tts_model` | cosyvoice-v2 | **换 voice 必须同步换 model** |
| `tts_voice` | longshu_v2 | 温暖男声；v2 下可选其它 `*_v2` 人物 |

参数经 launch 文件 `parameters=[params_file]` 加载，也可命令行覆盖：`ros2 launch voice_interaction voice_interaction.launch.py energy_threshold:=300`。

## 11. 构建、部署与运行

### 11.1 依赖

- ROS2 Humble（机器人自带）
- `interface_protocol` 消息包——编译 Native SDK 时自动生成（`engineai_robotics_native_sdk/src/protocol/interface_protocol`）
- Python：`dashscope pyaudio numpy`（可选 `webrtcvad`）
- 系统：`ffmpeg`（MP3 转 WAV）和 ALSA `aplay`（播放 WAV；通常由 `alsa-utils` 提供），例如：`sudo apt install ffmpeg alsa-utils`
- 阿里云 `DASHSCOPE_API_KEY` 环境变量

### 11.2 推荐运行方式（run_voice.sh）

`.bashrc` 可能 source 了旧工作区，直接 `ros2 launch` 会跑旧代码（提示词还停留在“众擎”）。**必须用 `run_voice.sh` 启动**，它强制加载本工作区：

```bash
~/voice_interaction_test_ws/run_voice.sh
```

## 12. 质检清单与常见问题

### 12.1 编译

```
colcon build --packages-select voice_interaction
```

- **编译找不到 interface_protocol？** 把 `engineai_robotics_native_sdk/src/protocol/interface_protocol` 拷入同工作区 src 一起编，或先 source Native SDK 的 `build/ros2_env/install/setup.bash`。
- **运行时 import 失败（MotionGesture）？** 确认 `engineai_ros2_ws/install/setup.bash` 排在旧环境之前（见 §11.2）。

### 12.2 运行

启动后看日志：应出现 `语音交互节点启动成功` 与 `请先说：你好小智`。测试口令：

| 口令 | 预期 |
|------|------|
| “你好小智” | 唤醒，等下一句 |
| “你好小智，跟着我” | 开始跟随 |
| “跟着我” / “停止跟随” | 视觉跟随开/停（安全指令，直连） |
| “直行/停止”交警手势 | 手势动作（站定后） |
| “急停/紧急停止” | 速度归零 + passive（不播报） |
| “你好” | 闲聊（LLM） |

### 12.3 常见问题速查

| 现象 | 排查 |
|------|------|
| ASR 无结果 | `echo $DASHSCOPE_API_KEY`；`arecord -l` 确认有 mic；调低 `energy_threshold` |
| TTS 无声 | 装 ffmpeg；`cosyvoice-v2` 须配 `*_v2` voice |
| 机器人不动 | `ros2 topic echo /motion/motion_state` 看状态；walk 需先 pd_stand→rl_basic；`ROS_DOMAIN_ID=69` |
| id 无法连上运控 | `ros2 topic echo /motion/motion_state` 是否收（跳过 BEST_EFFORT 问题） |
| 误触发太多 | 调高 `energy_threshold`；或后续集成唤醒词引擎 |
| 说话中打断/站立化无反应 | 检查跟随安全桥 topic 是否在转发、motion_state 订阅是否达 |

## 13. 安全提示（真机）

- 真机测试先吊架或空旷场地，`walk` 从 0.1m/s 起步。
- 跟随中是“主要行走方式”，行走速度由安全桥收敛，NO 手动 walk。
- `emergency_stop` 随时可用，立即切 passive。
- `walk` **没有自动超时**：会以 100Hz 持续发速度直到收到停止指令，停步必须主动发 `walk(0,0,0)`（普通停下）或 `emergency_stop`（急停）。唯一的超时在**自动切链**阶段：每级状态切换 `_WALK_STEP_TIMEOUT=8s`，超时即取消本次行走命令。（README 所述“2s 超时保护”在代码中不存在，勿依赖。）
- 麦克风持续监听，云端 ASR 会上传音频，注意隐私。
